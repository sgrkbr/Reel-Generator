# 12. 収益化計画 (Monetization Plan)

本ドキュメントは docs/01〜11 で構築した「Claude (脚本・運用) × Higgsfield MCP (生成) × GitHub Actions (自動化)」体制を **収益に接続する** ための計画。KPI (docs/06) のフォロワー/再生マイルストーンを収益ゲートとして再利用する。

> 数値 (RPM・参加条件) は 2026-07 時点の目安。プラットフォーム規約は頻繁に変わるため、**各 Phase 着手時に必ず一次情報を再確認**すること。

---

## 0. 前提: いま持っている資産

| 資産 | 収益化への意味 |
| ---- | -------------- |
| Higgsfield MCP + 実測コスト (30s ネタ ≒ **135 credits** / 5s×6ショット) | 1本あたりの限界費用が既知 → ユニットエコノミクスが計算できる |
| Claude (脚本量産・KPI 分析・A/B バリエーション生成) | ネタ供給がボトルネックにならない。人件費ゼロで週5本体制が可能 |
| 自動化パイプライン (generate.yml / publish.yml / Postiz) | 投稿頻度を落とさず横展開できる = 収益源の多重化が低コスト |
| 3チャネル同時配信 (TikTok / IG Reels / YT Shorts) | 単一プラットフォーム依存リスクの回避。収益プログラムも3系統 |
| Higgsfield `dubbing` ツール (18言語対応) | 同じ動画を多言語チャネルに展開 → 追加制作費ほぼゼロで再生母数を増やせる |

## 1. 収益モデル全体像 — 5層スタック

収益源は「必要フォロワー規模」順に積み上げる。**上の層が下の層を無効化しない** (全部並走できる)。

| 層 | 収益源 | 起動条件 (目安) | 期待レンジ | 依存 |
| -- | ------ | --------------- | ---------- | ---- |
| M1 | プラットフォーム収益分配 (YT Shorts / TikTok Creator Rewards) | YT: 1,000登録 + Shorts 1,000万再生/90日 · TikTok: 10,000フォロワー + 10万再生/30日 | 低単価・自動 | 再生数 |
| M2 | アフィリエイト (Amazon Associates 等 + link-in-bio) | フォロワー ~5,000 から可 | 中 | ネタとの親和性 |
| M3 | ブランド案件 / UGC 制作受託 | 10,000〜50,000 フォロワー | 高単価・不定期 | アカウントの信頼性 |
| M4 | 自社商品 (デジタルグッズ / テンプレ / 制作パイプライン自体の商品化) | オーディエンス確立後 | 高マージン | ブランド |
| M5 | 資産ライセンス / チャネル売却 (オプション) | 出口戦略 | 一括 | 全部 |

## 2. Phase M1: プラットフォーム収益分配

### 2.1 参加条件マトリクス (2026-07 時点・要再確認)

| プラットフォーム | プログラム | 条件 | RPM 目安 | 備考 |
| ---------------- | ---------- | ---- | -------- | ---- |
| YouTube Shorts | YPP (Shorts 収益分配) | 登録 1,000 + Shorts 1,000万再生/90日 (or 4,000 時間 + 1,000登録) | $0.05〜0.15 / 1k | 低単価だが完全自動。**最初に到達しやすい** |
| TikTok | Creator Rewards Program | フォロワー 10,000 + 再生 10万/30日 + 18歳以上 + **1分超のオリジナル動画のみ対象** | $0.40〜1.00 / 1k (対象動画のみ) | 単価は高いが「1分超」制約が本企画の 30-60s 方針と衝突 → §2.3 |
| Instagram Reels | ボーナス/ギフト | 招待制・地域限定 | 期待値ほぼ0 | 収益源ではなく発見面 (M2/M3 への導線) と割り切る |

### 2.2 AI 生成コンテンツのポリシーリスク (最重要)

- **YouTube**: 2025年の「inauthentic content」ポリシー強化により、**量産型・繰り返し感のある AI コンテンツは収益化剥奪リスク**がある。対策: (1) 脚本・オチ・キャラ設定に一貫した独自性を出す (Claude の脚本が付加価値の証明になる)、(2) 合成メディアの開示フラグを必ず設定、(3) 同一テンプレの機械的連投を避け、シリーズ内でも構成を変える。
- **TikTok**: AI 生成コンテンツのラベル付けが義務。未ラベルはリーチ抑制・削除リスク。パイプラインの `publish` 段階で **AIGC ラベルを自動付与** する (channels.yaml にフラグ追加)。
- **含意**: 「完全無人量産」ではなく「AI 制作 × 人間の企画・品質ゲート」であることが、規約面でも収益の生命線。docs/07 の半自動方針 (人がレビュー→承認) はそのまま維持する。

### 2.3 TikTok「1分超」問題への尺戦略

Creator Rewards の対象は 1分超動画のみ。対応方針:

1. **基本は現行 35-55s を維持** (完視聴率が KPI の生命線。docs/02 のバズパターンを崩さない)
2. フォロワー 5,000 到達後、**週1本だけ 60-90s の「拡張版」を実験** — 2ネタ連結 ("Part 1 / Part 2" 構成) or Inner Voice モノローグの長尺化
3. 拡張版の完視聴率が短尺の 70% を維持できるなら本数を増やす。できないなら TikTok は M2/M3 の集客面と割り切り、収益分配は YouTube に寄せる
4. コスト影響: 60s 版 ≒ **270 credits/本** (倍)。credits 予算ゲート (docs/07) の上限を尺別に設定する

### 2.4 多言語展開 (dubbing レバー)

Higgsfield `dubbing` で英語版を日本語・スペイン語・ポルトガル語等へ変換 → 言語別サブチャネル運用。

- 追加費用: dubbing クレジットのみ (新規生成不要)
- 優先順: **スペイン語 (人口最大の未開拓圏) → ポルトガル語 → 日本語**
- 起動条件: 英語版で「勝ちネタ」が10本溜まってから (負けネタを翻訳しても負ける)

## 3. Phase M2: アフィリエイト

カップルあるあるネタは **商品文脈と自然に接続する** (Costco ネタ→日用品、Plant Parent→園芸、Streaming Audit→サブスク管理)。

- **リンク設置**: link-in-bio ツール (Beacons / Linktree) を3チャネル共通で設置
- **プログラム**: Amazon Associates (US) を軸に、ネタと相性の良い D2C (カップル向けゲーム、マグ、カレンダー共有アプリ) のアフィリエイトを追加
- **運用**: ネタの frontmatter に `affiliate_hook` フィールドを追加し、該当ネタ投稿時にキャプション/コメント欄へ自動挿入 (publish パイプラインの小改修)
- **注意**: 動画本編には広告色を出さない。コメント欄固定 + bio 誘導のみ。FTC 開示 (#ad / #affiliate) を自動付与

## 4. Phase M3: ブランド案件 / UGC 受託

- 10k フォロワー超えたら TikTok Creator Marketplace / Collabstr 等に登録
- 「2D アニメでブランドメッセージをあるある化する」枠は実写 UGC より競合が少ない — **アニメキャラがブランド商品を使うカスタムネタ** を商品として定義 (相場: フォロワー 10k-50k で $200〜800/本 目安)
- 制作費 135〜270 credits/本 に対し受託単価が2桁上 → **最も利益率が高い層**。案件用テンプレ (納期・修正回数・使用権) を先に文書化しておく
- Claude の役割: ブランド指定を frontmatter 化 → 既存パイプラインがそのまま流れる (受託でも限界費用が変わらない)

## 5. Phase M4: 自社商品

オーディエンス確立後の高マージン層。候補を優先度順に:

1. **デジタルグッズ**: wife & husband の LINE スタンプ的ステッカーパック、壁紙、カップル向けプリンタブル (会話カード等) — Gumroad/Etsy、制作は既存キャラアセット流用
2. **パイプラインの商品化**: 本リポジトリの仕組み自体 (Higgsfield × Claude × 自動投稿) を、テンプレ + セットアップガイドとして販売 or 教材化。「作っている過程」を発信する第2アカウントが M4 の集客になる
3. **物販 (POD)**: ネタ内の名台詞 ("He said fine" 等) の Tシャツ/マグ — Printful 連携、在庫リスクゼロ

## 6. ユニットエコノミクス

### 1本あたりコスト (実測ベース)

```
30-55s ネタ: ~135 credits + インフラ按分 (~$0.2)
60-90s ネタ: ~270 credits
月産20本 (週5本):  ~2,700 credits/月 + $5 (Actions/R2/Postiz)
```

credits の円換算は契約プランの単価に依存するため、`credits単価 = プラン月額 ÷ 付与credits` で各自算出して下表に埋めること。

### 損益分岐の目安 (YouTube Shorts RPM $0.10 と仮定)

| 月間費用仮定 | 必要月間再生数 (YT のみで回収) |
| ------------ | ------------------------------ |
| $30 (2,700 credits ≒ $25 + インフラ $5) | 30万再生/月 |
| $60 (60s版込み) | 60万再生/月 |

docs/06 の 90日マイルストーン (平均5万再生 × 月20本 = 100万再生/月) が達成できれば、**M1 だけで制作費は回収できる**計算。M2 以降は純増。

### 収益シナリオ (90日到達時、月100万再生の配分想定)

| 収益源 | 試算 | 月額目安 |
| ------ | ---- | -------- |
| YT Shorts (40万再生) | RPM $0.10 | $40 |
| TikTok CRP (拡張版のみ 10万再生) | RPM $0.60 | $60 |
| アフィリエイト | CTR 0.5% × CVR 2% × 単価 $2 | $20〜40 |
| ブランド案件 | 月1本 $300 | $300 |
| **合計** | | **$420〜440/月** |

→ 収益の柱は当面 **M3 (案件)**。M1 は「費用の自動回収装置」、M2 は「常時微収入」、M4 は 6ヶ月目以降の伸びしろ、と位置づける。

## 7. Claude の収益化フェーズでの役割

| タスク | 使い方 |
| ------ | ------ |
| ネタ量産 (31〜90本目) | docs/02 のバズパターン + 週次レビューの学びを与えて 10本/週 生成 → 人が選別 |
| A/B バリエーション | 勝ちネタのフック違い・オチ違いを自動生成 (docs/06 の A/B 運用に接続) |

| 案件対応 | ブランドブリーフ → frontmatter 変換、修正対応の脚本リライト |
| 多言語 QA | dubbing 出力の訳文チェック・キャプション翻訳 |

## 8. 収益ゲート付きロードマップ

docs/06 のマイルストーンに収益アクションを紐付ける。**ゲート未達なら次の収益施策に手を出さない** (分散が最大の敵)。

| 時期 | フォロワーゲート (TikTok) | 収益アクション |
| ---- | ------------------------- | -------------- |
| Day 0-30 | — | 投稿の型を固める。**収益施策ゼロ**。YT/TikTok の収益プログラム条件と AI ポリシーの最新版を確認、AIGC ラベル自動付与を実装 |
| Day 30-60 | 1,000 | link-in-bio 設置、Amazon Associates 申請 (M2 準備)。YT 登録 1,000 を先に狙う導線 (キャプションで YT 誘導) |
| Day 60-90 | 5,000 | 60-90s 拡張版の実験開始 (§2.3)。dubbing 1言語目のテスト |
| Day 90+ | 10,000 | TikTok CRP + Creator Marketplace 登録、YPP 申請 (条件充足次第)。案件営業テンプレ整備 (M3) |
| Month 6+ | 50,000 | M4 着手判断 (デジタルグッズから)。多言語チャネル本格化 |
